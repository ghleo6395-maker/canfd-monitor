# win_sim：车窗开关模拟器驱动

APM 售后测试扩展模块。监控器在 APM 的车窗开关输入上模拟按键，同时用 CAN 读回 APM 识别出的开关状态，用来测出各档位的电压门限。没有键值表时，也可以并在原车开关上被动学习每个档位。驱动按 APM 车窗开关模拟规范（apm.md）实现，并针对 Hardware-C 新增的第 12 页第 3 版电路做了调整。C99，不用动态内存，裸机和 RTOS 都能用。

**思路：APM 只认它引脚上的电压。** 学习时只记电压（空闲和各档），发出时用电阻把引脚拉到同样的电压。驱动先辨识 APM 一侧的等效电源（开路电压 V0、内阻 Rth），再按 V = V0 × R / (R + Rth) 求电阻，按回读微调。所以不依赖某一台 APM 的上拉阻值和电压。

**硬件状态：第 12 页还只是提案。** 它尚未加入仓库里 11 页的 `Hardware-C-schematic.pdf`，现有固件也还没有移植到 Hardware-C。因此本目录只提供与平台无关的驱动和主机测试，没有接入 `platform/` 和主循环。

## 第 12 页第 3 版电路

4 路接口 K1–K4 共用一套 15 位电阻阵，同一时刻只接通一路；每路另有一个空闲保持支路，4 路可以同时保持各自的空闲电平。

| 功能 | 器件和引脚 |
| --- | --- |
| I/O 扩展 | U801 TCA9539PWR @0x74、U808 TCA9539PWR @0x75（A0 = +3V3），挂在 I2C4（PD12 SCL / PD13 SDA），与 U111 TUSB320、J302 共用总线 |
| 复位和使能 | PG2 = WS_RST_N，经 R814 10 kΩ 下拉。PG2 低时两片扩展复位、电阻阵全关、空闲继电器全断、升压关断；同时经 Q808B 反相成 CH_EN_N，4 路通道继电器全断 |
| 电阻阵 | b0–b11 = R801–R812（200、390、820、1.6k、3.3k、6.2k、13k、24k、47k、91k、180k、360k Ω），b12 = R831（100 Ω），b13 = R845（47 Ω），b14 = R846（150 kΩ），1%；BSS138DW（Q801–Q806、Q808A、Q809）。b0–b12 由 U801 控制，b13/b14 由 U808 的 P07/P14 控制 |
| 0 Ω 直通 | Q807 AO3400A，由 U801 P14 控制 |
| 通道选择 | U801 P16/P17 = CH_A0/CH_A1 → U806 SN74LVC139A 译码 → U802–U805 TLP176AM 光耦继电器 |
| 空闲保持 | 每路：WS_KFk → TLP176AM（U813–U816）→ 2.2 kΩ（R827–R830）→ AD5292BRUZ-50（U809–U812）W 端，B 端回 WS_RET。U808 位操作 SPI（P00 SCLK、P01 DIN、P02–P05 SYNC），P10–P13 驱动继电器，P06 = VPOT_EN |
| 电位器电源 | U817 TPS61040 把 +5V 升到 WS_VPOT ≈ 25.9 V（R841 1 MΩ / R842 49.9 kΩ） |
| 每路保护 | F801–F804 50 mA PTC，D801–D804 SMF15CA |
| 回读 | 每路接口侧 300 kΩ（R815–R818）→ U807 CD74HC4052 选通 → R819 56 kΩ + C802 1 nF → PC2_C = WS_ADC；÷ 6.36，量程约 21 V，时间常数约 47 µs |
| 接口 | J801 KF2EDGR-3.81-8P，奇数脚 K1–K4，偶数脚 WS_RET（经 R844 0 Ω 单点接 GND） |

位映射和上电顺序见 `win_sim_tca9539.h` 的注释。原理图、元件清单和逐脚网表见 `docs/apm-keysim/schematic/page12-rev3.html`。

## 运行

从仓库根目录执行：

```sh
make -C fw test-winsim
make -C fw winsim-example
```

`make -C fw test` 也会运行 `test_win_sim`。`services/winsim/*.c` 由 `services/*/*.c` 通配编进主机测试、模拟器动态库和 ARM 固件。ARM 固件里目前没有调用方，`--gc-sections` 会把它们丢掉。

## 用法

```c
static winsim_ctx_t ws;                       // 约 1.7 KB
winsim_init(&ws, &hal, NULL);

// 切到 K2 并辨识：APM 一侧的 V0、Rth 和这一路的串联电阻（会短暂接通 0 Ω 直通和一个已知电阻）
float r_series;
winsim_select_channel(&ws, 1, true, &r_series);

// 模拟按键：按目标电压（按回读微调）或阻值
winsim_state_t st;
winsim_set_voltage(&ws, 3480, &st);
winsim_set_hiz(&ws);                          // 松开（电阻阵高阻，空闲保持不受影响）

// 被动学习：原车开关并在这一路，电阻阵保持高阻
winsim_learn_t l;
uint16_t idle, mv, key_mv;
winsim_probe_open_voltage(&ws, &idle);        // 开关松开时：这就是要记的空闲电压
winsim_learn_begin(&l, &ws.cfg, idle);
for (;;) {                                    // 每 50 ms 一次
    winsim_measure(&ws, &mv);
    if (winsim_learn_feed(&l, mv, 50, &key_mv))
        save_key(key_mv, winsim_equiv_ohm(&ws, key_mv));
}

// 原车开关拔掉以后：在 K4 保持学到的空闲电压
winsim_idle_t id;
winsim_idle_hold(&ws, 3, idle_k4, &id);       // id.on = false 表示不需要（开关还接着或空闲为开路）
winsim_idle_release(&ws, 3);                  // 接回原车开关前先断开
```

- **辨识**：高阻量 V0（同时用 24 次、间隔 1 ms 的采样判断是不是脉冲上拉），接 0 Ω 直通量一次，再接一个阻值接近内阻的组合量一次，三式解出 Rth 和串联电阻 rs：a = V直通 / (V0 − V直通) = (rs + R直通) / Rth，b = V1 / (V0 − V1) = (rs + R1) / Rth。读数偏离中间太多时按算出的 Rth 再挑一次已知电阻。PTC 断开等结果不合理时返回 `WINSIM_ERR_CALIBRATION`，保留原值。这一路的空闲支路接着时照常测，结果里扣掉它。
- **求解和微调**：模型里含 356 kΩ 回读负载和接着的空闲支路。按回读微调最多 `trim_steps` 次（默认 2）：用这一档的实测值算出局部等效内阻，重新求解，只接受更好的结果。微调能吸收电阻误差和模型偏差，但绕不开坏掉的位，扫描时按理论值校验仍会报出来。
- **换组合**：既有要断开的位又有要接通的位时，先只留两者都有的位再写新组合，中间态阻值总是更高（电压更接近空闲）。
- **空闲保持**：先断开这一路的空闲支路量开路电压 V0；学到的空闲电压 ≥ V0 − 30 mV 时不接。否则把电位器放到最大阻值接通，用这一点算 Rth，再算码值、按回读微调。整个过程接口电压都在 V0 和空闲电压之间，不会出现比空闲更低（像按键）的电压。所需电阻小于约 2.3 kΩ、大于约 52 kΩ，或电流超过 1.8 mA 时返回 `WINSIM_ERR_RANGE`，支路保持断开。
- **脉冲上拉**：识别出来后，这一路的回读都按“24 次采样里高于最大最小值中点的平均”取值，只算上拉接通期间。
- **换通道**：先把电阻阵切到高阻，再改通道地址，等 `channel_switch_ms`（默认 5 ms）。换通道会清掉空载电压，下次设置时重新探测。辨识结果按通道保存。
- **过压锁定**：默认门限 5.5 V。触发时电阻阵切高阻、所有空闲支路断开、关升压，不随换通道解除；换到正常的通道后调用 `winsim_clear_ovp()` 重新检测。上拉到蓄电池电压的车型把 `ovp_threshold_mv` 调到 16000（回读量程约 21 V）。
- **学习规则**：低于空闲电压 150 mV 算按下，相邻采样差 ≤ 25 mV 持续 500 ms 后记录一档（取稳定段平均值），之后要回到空闲附近才能学下一档。三个参数都在 `winsim_cfg_t` 里。

## 界面

`services/keysim/` 把驱动包装成界面用的非阻塞状态机，`app_tick()` 每个节拍推进它；界面页面在 `app/ui/core/ui_sm.c`。

- **入口：** 主页第 7 格“按键模拟”，主页随之变成 4×2。板上没有这部分硬件时（当前的 Rev D/E 目标）不显示入口，keysim 编译成空壳，不分配驱动上下文。将来 Hardware-C 目标定义 `CANFD_WINSIM_HW` 并实现 `port_keysim_hal()`、`port_keysim_apm_state()` 即可启用。
- **按键模拟（总览）：** K1–K4 各一行，显示是否接通、键值表和空闲保持；APM 供电一行；全部松开。OK 一路就切换并辨识，提示里给出辨识出的 APM 上拉。
- **K*n* 按键模拟（通道页）：** 接口电压和 APM 判定、按法（点按 300 ms / 保持）、键值表里的各键、手动电压、全部松开、学习键值、门限扫描、辨识（APM 上拉、是否脉冲供电、串联电阻，OK 重新辨识）、空闲保持、键值表。
- **空闲保持：** 默认关。原车开关拔掉后在通道页 OK 打开：原车开关还在线时显示“现在不需要”，拔掉后后台发现开路电压升高会自动接通；保持中每路约 1.2 s 检查一次，发现接口被拉低 150 mV 以上（原车开关接回？）就断开并提示。**接回原车开关前要先关**：两者并联时 APM 可能把它看成一次按键，后台检查只能在约 1.2 s 内发现。没有学到空闲电压（扫描得到的表）时不能打开。
- **学习键值：** OK 开始后每 50 ms 测一次接口电压（开始前断开这一路的空闲支路），按住原车开关一个档位 0.5 秒自动记录一档，显示电压和反推的开关电阻；保存后成为这一路的键值表，开始时测到的空闲电压一起存下。
- **门限扫描：** 从 4.8 V 每 50 mV 往下设，每档停 30 ms 读 APM 开关状态，记录门限；保存时每档取中点，沿用这一路以前学到的空闲电压。
- **安全：** 进出这几页、长按回主页、关机时都会停止学习 / 扫描并松开（空闲保持不受影响）；过压时锁定并断开所有空闲支路，直到在总览里重新检测。
- **键值表存 SD 卡：** 每路一个文件 `/APMKEY/K1.TXT … K4.TXT`，格式见 `services/keysim/keysim_file.h`（第 3 版多了可选的 `idle=` 一行，电压上限 16000 mV）。板级和模拟器的存储方式与第 2 版相同。
- **还没做：** 扫描用的 CAN 开关状态信号还没有配置界面；空闲保持的开关状态不跨重启保存（开机都是关）；“按住才生效”的按法需要触摸的按下 / 抬起事件。设备字库没有 Ω，界面里阻值写成“欧 / 千欧”。

桌面模拟器（`make -C fw sim`）右侧“环境”里有 APM 按键模拟台架：唤醒或休眠 APM、给每一路接上或断开原车开关、按住某个档位、模拟误接 12 V，第 3 版加了每路的 APM 上拉（1–10 kΩ）和原车开关松开时的电阻（开路、4.7/10/22 kΩ）。

## 与 apm.md 的差异

| apm.md | 本实现 | 原因 |
| --- | --- | --- |
| 8 位电阻阵，`uint8_t mask`，`r_lut[256]` | 15 位，`uint16_t mask`，没有查找表，每次遍历 | 8 位达不到 25 mV 精度；b12、b13 让低阻端够得着 200 mV，b14 补 10 kΩ 上拉时 4.5 V 附近的台阶；15 位的表要 128 KB，遍历只要几毫秒 |
| 按固定的 2.2 kΩ 上拉求解 | 辨识每一路的 V0、Rth，再按回读微调 | 换车型上拉不同；这是“对每辆车都行”的前提 |
| 1 路 | 4 路共用电阻阵，`select_channel()` 加进 HAL | 同一时刻只按一路，复用一套电阻阵；译码器保证不会同时接通两路 |
| — | 每路空闲保持（`idle_*` 三个 HAL 回调） | 原车开关空闲时接着电阻的车，拔掉开关后 4 路都要保持各自的空闲电平 |
| 74HCT595，`/OE` 上拉 | 两片 TCA9539，RESET 下拉到 PG2 | 主控只剩 PG2、PC2_C 两个空闲脚；HAL 名称不变，映射见 `win_sim_tca9539.h` |
| 回读 1:1，负载 200 kΩ | 300k/56k，负载 356 kΩ，取在各路接口侧 | 误接 12 V 时 ADC 脚不超过 3.3 V，量程够测上拉到蓄电池的输入；接口侧回读才能被动学习 |
| `winsim_state_t.mask_595` | `mask`，另加 `channel`、`target_mv`、`trims` | 控制字不再来自 595；回调里需要知道通道、目标值和微调次数 |
| 扫描中按目标值校验 | 扫描中按理论值校验，不微调 | 0 mV 附近无档位，按目标值校验会误报 |

## 接入 Hardware-C 固件

以下内容要等 Hardware-C 板级移植完成后再做。

1. 在板级代码里实现 `winsim_tca9539_port_t` 的四个回调，再用 `winsim_tca9539_bind()` 得到 `winsim_hal_t`（含空闲保持的三个回调）：
   ```c
   static bool ws_i2c_write(uint8_t addr7, uint8_t reg, const uint8_t *d, uint8_t n)
   {
       return HAL_I2C_Mem_Write(&hi2c4, (uint16_t)(addr7 << 1), reg, I2C_MEMADD_SIZE_8BIT,
                                (uint8_t *)d, n, 5) == HAL_OK;
   }
   static void ws_reset_pin(bool high)
   {
       HAL_GPIO_WritePin(GPIOG, GPIO_PIN_2, high ? GPIO_PIN_SET : GPIO_PIN_RESET);
   }
   ```
   `adc_read_raw` 读 ADC3_INP0（PC2_C），用较长的采样时间。
2. PG2 配置为推挽输出，初始低电平。PC2_C 保持模拟输入，SYSCFG 模拟开关保持默认的断开状态即可。
3. 在 `HardFault_Handler` 和致命错误处理里先调用 `winsim_tca9539_emergency_off()`。
4. I2C4 上还有 U111 TUSB320。两边都只能在前台循环里访问，不要在中断里调用本模块。
5. **阻塞时间：** 每次设置约等待 `settle_delay_ms`（10 ms），微调每次再加一次；换通道并辨识约 60 ms（含 24 ms 的脉冲判断）；建立一路空闲保持约 60–90 ms，其中每次写电位器是 68 次单字节 I2C 写；4800 到 0 mV、步长 50 mV、每档保持 30 ms 的扫描约 4 s。在裸机主循环里，`delay_ms` 回调必须在等待期间继续处理 CAN 采集、USB 和显示，否则会丢帧。FreeRTOS 版本可以放进独立任务。
6. 求解用了双精度累加，Cortex-M7 的 FPv5-D16 有硬件双精度。

## 已验证和未验证

- **已验证：** 驱动测试 20 组共 3630 项检查、界面测试 `test_keysim_ui` 612 项（含空闲保持、10 kΩ 上拉的 APM、SD 卡读写、断电重启、拔插卡、写保护）、文件格式测试 58 项、板级 SD 存储测试 `test_storage_sd_winsim` 全部通过，在 ASan/UBSan 下运行。
- **精度（仿真）：** 200–4600 mV 每 200 mV 一个测试点，辨识后按回读微调。标称器件、串联 12.4 Ω 时最差 7 mV；20 组随机器件（1% 电阻、APM 上拉 ±1%、导通电阻偏离模型 2 Ω、串联 5–17 Ω）最差 10 mV。APM 上拉 1 kΩ、1.5 kΩ、2.2 kΩ、4.7 kΩ、10 kΩ（5 V）和 3.3 kΩ（3.3 V），每 100 mV 一个点、1% 随机器件：最差 6、11、13、15、28、6 mV；辨识出的内阻误差不超过 0.7%。脉冲上拉（每 8 ms 接通 3 ms）最差 2 mV。
- **空闲保持（仿真）：** 原车开关空闲 2.7 k、4.7 k、10 k、22 k、47 kΩ 都能保持，回读与目标差不超过 10 mV（2.7 kΩ 时一个码值约 22 mV）；建立过程中接口最低读数没有低于空闲电压。1 kΩ、150 kΩ 和电流超限的情况返回超出范围。
- **示例：** 示例扫描在 K3 上还原出了仿真 APM 设定的 5 个门限。
- **ARM 编译：** 用 Arm GNU Toolchain 15.2.Rel1 跑 `make -C fw -f Makefile.arm BOARD=reve check` 通过。Rev E 上 keysim 是空壳。打开 `CANFD_WINSIM_HW` 的驱动、适配、服务和文件格式代码用 Arm GCC（`-Wall -Wextra -Werror -Wdouble-promotion`）单独编译没有告警；代码约 13.7 KB，RAM 约 1.7 KB（第 2 版约 33 KB），驱动函数栈帧最大 184 B（`winsim_init`）。
- **未验证：** STM32 平台回调、实板 I2C、ADC 和 SPI 时序、与 APM 的联调；遍历求解在目标板上的实际耗时；PTC 的具体料号和阻值。
